Those are byte for byte the numbers run59's image produced, so adding the driver to
the kernel did not move the prelinked kexts: the prelink layout is a function of the
kext set, not of the kernel's own size.  Worth knowing, but it is not what the build
relies on -- it relies on the record plus `--verify`.

This run commits that record as boards/ios16/virtio-record.json, so the archive is
bound to real addresses instead of the stubs, and "What came out" re-resolves them
against the finished image.  If the kernel that comes out says "all 11 bindings still
current", it is the first one whose NativeVirtioBlock can actually probe a
virtio-mmio block device.
